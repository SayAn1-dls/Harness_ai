# Decisions

Append-only product decisions. Prefer `DECISION` events in `events.jsonl` for task-local choices.

- 2026-09-26: Python 3.11+ harness; pydantic schemas; filesystem event sourcing.  
- 2026-09-26: Model adapter protocol; mock default; OpenAI-compatible optional.  
- 2026-09-26: tree-sitter not required for v1; Python `ast` + regex. Embeddings secondary.  
- 2026-09-26: unittest for target repos so verification does not depend on pytest being installed in the target.  
- 2026-09-26: Human approval required before `gh pr create`.
- 2026-09-26: LCC is its own git repo (the enclosing `~/.git` is the user's home dir and must not be touched). Work on `agent/core-loop`.
- 2026-09-26: Real backends are DeepSeek and Gemini via their OpenAI-compatible chat-completions + function-calling endpoints (one adapter, presets in `lcc.model.PRESETS`). A missing API key is an error; there is no silent fallback to mock.
- 2026-09-26: The coder is a tool-using loop (`lcc.agent_loop`), not single-shot JSON. Observations are bounded (6k chars); identical calls are warned then stopped; tokens and runtime are metered per model call (`MODEL_CALL` events).
- 2026-09-26: Scope policy: forbidden paths (`harness/**`, `.git/**`, plan.forbidden_files) are hard-blocked; writes outside plan.allowed_files are allowed but recorded as `scope_expansions` and shown to the reviewer (`scope_mode="strict"` refuses them instead).
- 2026-09-26: Verification needs proof, not just a green suite: a baseline run is recorded before the first attempt; a pass requires either previously failing tests now passing, or changed/new tests that fail on the base code (sources temporarily reverted) and pass with the change. No changes means not verified. Zero collected tests is not a pass.
- 2026-09-26: Intake escalates on `blocking_ambiguities` (a question only the requester can answer) instead of guessing.
- 2026-09-26: Context gate is enforced for repos with more than 8 files: below 75 after expansion and a read-only context-agent pass means ESCALATED/missing_context. The snapshot score was recalibrated to measure relevance (the old score rewarded file count). Known weakness: `relevant_files` is self-referential (top-ranked vs selected).
- 2026-09-26: Compaction is deterministic: once an agent's working context exceeds 24k tokens, old tool observations become one-line stubs (the 6 most recent are kept). No summarization model call.
- 2026-09-26: Routing is opt-in: `LCC_MODEL_FAST` serves intake/recovery/review/context; `LCC_MODEL_STRONG` serves planner/coder on Lane C or after 2+ failed attempts.
- 2026-09-26: Hackathon evaluation interface. The root `Makefile` exposes `setup`, `run`, `test` and `clean` (plus `eval`, `doctor` and `distclean`). `make run` launches `lcc start`, an evaluation-mode session that accepts an issue as a GitHub URL, a file, pasted text, or stdin. Harness code runs from source (`PYTHONPATH=src python -m lcc`), so it never depends on editable-install `.pth` files.
- 2026-09-26: The only credential is `AI_API_KEY`, read from the environment at runtime and never written to files. Per-provider variables remain only as a local-dev fallback. The model is defined in `lcc.config.toml`: temperature 0.0, and `seed` is sent only to providers that accept it. `provider="auto"` maps the key format to an OpenAI-compatible preset and probes `/models` only for an ambiguous `sk-` key. The environment variables `LCC_PROVIDER`, `LCC_MODEL` and `LCC_BASE_URL` override the config without code edits.
- 2026-09-26: Target repositories are cloned into `workspaces/` (URLs) or used in place (local paths). Each gets an isolated venv (`workspaces/.venv-<name>`) with its dependencies, and `LCC_TEST_PYTHON` points the test tools at it. After each issue, unverified work is parked as a commit on the task branch and the repo returns to its original branch. `/harness/` is added to the target's `.git/info/exclude`.
- 2026-09-26: QA hardening of `make run`. Before a run, the user's uncommitted changes in the target are stashed and restored afterwards. They are never committed into the fix and cannot be destroyed by a rollback. A re-run of an issue whose `agent/<id>` branch exists gets `<id>-2`, `<id>-3` and so on, so it starts clean and does not overwrite the earlier patch. A repo with no commits gets a snapshot commit. Empty piped input, and setup errors, exit with code 2 instead of 0 or a traceback.
- 2026-09-27: The organisers announced that the final evaluation uses DeepSeek and Qwen models. The `qwen` (DashScope international) and `qwen-cn` presets were added beside `deepseek`. With `provider="auto"`, an ambiguous `sk-` key is checked with `GET /models` (no tokens spent) against DeepSeek, then DashScope international, then DashScope China, and never against any other vendor. The answer is cached for the process.
- 2026-09-27: `AI_API_KEY` is the only credential variable; the per-provider fallbacks were removed. A placeholder key (for example `your-key`) is rejected before any request is made.
- 2026-09-27: Before any work, a preflight sends one tiny completion from `make run`, `make doctor` and `make eval`. Account errors are `fatal`: 401 key rejected, 402 balance, 403 not allowed, 404 or model-not-found, and the quota or arrearage texts. They stop the session or benchmark at once instead of being retried per task. An unpinned default model that the account does not serve falls back through the preset's list (deepseek-chat → deepseek-reasoner; qwen3-coder-plus → qwen-plus → qwen-max → qwen-turbo). A pinned model (`[model].model` / `LCC_MODEL`) never falls back.
- 2026-09-27: The provider adapts to the server. A rejected parameter (`enable_thinking` for Qwen3, `response_format`, `parallel_tool_calls`, `seed`, a large `max_tokens`) is fixed or dropped, retried once, and remembered. A server without function calling gets the tools described in the system prompt, and `<tool_call>{...}</tool_call>` blocks (Qwen/Hermes style) or fenced JSON calls are parsed from the reply. `<think>` reasoning is stripped. Assistant tool-call messages send `content: ""`, never null.
- 2026-09-27: Verification compares test sets with the baseline instead of requiring a fully green suite. Failing test IDs are parsed for pytest, unittest, go, cargo, jest/vitest and node tap. A change passes when no test that passed at baseline now fails (pass-to-pass), and a baseline failure now passes or a new or changed test fails on the base sources (fail-to-pass). A full suite that exceeds `run.test_timeout` (900 s) falls back to the targeted tests: changed tests, plus tests named after the changed modules.
- 2026-09-27: Token efficiency: a later read of the same lines replaces the earlier read with a stub; passing test runs render as one line and failing runs as failures only (pytest `-rfE --tb=short`); observations are capped at 5k chars; compaction starts at 16k tokens. The coder gets a warning 3 steps before `max_steps`. Tool schemas were shortened by about 40%. The coder prompt asks for independent lookups to be batched in one turn (Qwen presets send `parallel_tool_calls`). JSON agents use `response_format=json_object` where supported, to avoid repair calls. Issue text is cut to 8k chars. Lane A skips the planner model call. Measured with a scripted 16-step session and identical steps, prompt tokens fell from 120,783 to 97,424 (−19%).
- 2026-09-27: The coder tools now include `shell` (git-state and destructive commands blocked, including `git -C . reset`; timeout clamped to 1–600 s; `python` resolves to the target's venv) and `git_history` (log/blame). Search respects `.gitignore` and takes a regex and a path glob. `edit_file` tolerates trailing whitespace, CRLF and pasted `N| ` line prefixes, never guesses indentation, points at the closest lines on a miss, and supports `replace_all`.
- 2026-09-27: Repository handling. A local path that is not a git repository root is copied into `workspaces/`, so the harness never runs `git init` inside another repository. `BASE=<sha>`, `REPO=<url>@<ref>` or a `Base commit: <sha>` line pins the base commit (detached checkout, and the original branch is restored). JavaScript targets get `npm ci` / `npm install`. Go (`go test ./...`), Cargo and npm test commands are used for non-Python projects.
- 2026-09-27: `make test` runs the unit tests and the offline scripted benchmark on all 7 tasks, each graded by its hidden check (`--min-resolved 7`).
- 2026-09-27: Repo-only auto mode (`make auto REPO=<url>`, `lcc start --auto`, or a bare repository link pasted into `make run`). Candidates come from failing tests, ruff restricted to defect rules (`lcc.discover.DEFECT_RULES`; no style rules), and a token-bounded model audit of the highest-PageRank source files that must name a concrete trigger. They are ranked, de-duplicated and capped at `[auto].max_fixes`. Each runs through the normal pipeline, so a model finding that cannot be shown with a failing test is never verified and never PR'd. `TaskState.kind="optimize"` accepts a behavior-preserving change on proof level 3: the existing tests run and pass with no regressions. Verified fixes are pushed (to the repository with push access, otherwise to a fork via `gh repo fork`) as `lcc/<task-id>`, one PR per fix. The harness never merges (`assert_permitted` still denies MERGE_PR).
- 2026-09-27 (QA pass): Each item below was reproduced first, then fixed; tests are in `tests/test_qa_regressions.py`, and 15 of them fail on the pre-fix code. (1) Lint checks only the changed Python files, and fails only on diagnostics that the base versions of those files do not have. With ruff installed, one unrelated pre-existing error had blocked every fix: 5 iterations and 22 model calls, against 1 iteration and 5 calls now. (2) There is no recovery or replanning call once no iteration or budget is left. (3) The same failure signature twice stops before another recovery call; the signature falls back to the output tail when no failure keyword is present (lint output used to evade it). (4) Recovery receives the verifier's full output, including the proof, regression and lint notes, not just the raw (possibly green) test run. (5) A model reviewer can send a proven fix back at most once; after that its findings are advisory, while the deterministic security findings still block. (6) `finish` in the same turn as a failed edit is ignored. (7) Any tool exception (for example a non-integer line number) becomes an ERROR observation instead of crashing the task, and Latin-1 files are edited in their own encoding. (8) Model JSON is coerced safely: a string `"none"` in a list field is empty, not four characters (it used to escalate solvable tasks as "blocking ambiguity"), and non-numeric confidences or orders no longer crash. (9) `_is_test` recognises JS/TS `.test`/`.spec`, `__tests__/`, Ruby `_spec` and Java/C# `*Test`, and no longer matches `testament.py`. (10) `prepare_env` installs only the extras and dependency groups a project declares, because pip exits 0 for an unknown extra and `[dev]` test dependencies were never installed. (11) The repository scan prunes `node_modules` and similar directories instead of walking them. (12) Failing-test IDs with spaces are parsed, an issue file path is no longer mistaken for a repository, the JSON-mode prompt contains the lowercase word "json", and auto mode stops on a fatal account error.
- 2026-09-27: Leaner prompts, measured on the 7 scripted tasks with identical steps: 71,215 → 66,743 prompt tokens (−6.3%). Coder tool schemas went from 875 to 721 tokens per call: descriptions a model does not need were dropped, and `find_references` was removed from the coder, since `search_code` with regex `\bname\b` covers it; the context agent keeps it. Planner context was cut from 8×1500 to 6×1000 chars (replan 4×800), and reviewer test evidence from 2000 to 800 chars. The README was rewritten with animated SVGs (`docs/assets/`, CSS/SMIL, rendered by GitHub through `<img>`) and Mermaid diagrams, all checked to render.
- 2026-09-27 (acting on the 6/10 review): (1) Target code no longer sees credentials. `sandbox.child_env` strips `*KEY*`, `*TOKEN*`, `*SECRET*`, cloud, `GH_`/`GITHUB_` variables and the SSH agent from every test, shell, pip and npm child process. A `git` shim first on PATH refuses state-changing git inside the task repository, which closes the `subprocess.run(['git','reset'])` bypass of the text denylist. (2) `sandbox = "docker"` runs installs, tests and shell commands in a container with no network during tests, no credentials, and only the workspace plus a venv volume mounted. It is tested end to end: the key is absent, home is invisible, the network is unreachable, and the pipeline still verifies. (3) Real benchmark `benchmarks/real/`: 20 real bug-fix commits from 6 libraries were mined automatically (one small source change plus tests), and each was validated to fail at the parent commit and pass at the fix. Issue texts describe the symptom observed on the base commit, never the fix. `make bench-check` shows 20/20 valid, the oracle (reference fix replayed through the whole harness, explicitly not a model) at 20/20, and a do-nothing model at 0/20. (4) The metrics are measured, not constant. The context score's self-referential "relevant files" part and its constant rule and history points were replaced by named-target coverage. The intake score now measures concrete, issue-grounded criteria. The global score comes from verification evidence only, and "confidence decreasing" now means failing tests rose across attempts. (5) Auto mode opens draft PRs by default, asks before opening PRs on repositories without push access (non-interactive runs need PR=1), and stops at 3 open PRs per repository. (6) `.git/info/exclude` in targets also covers `*.egg-info/`, `__pycache__/`, `.pytest_cache/` and `node_modules/`, because editable installs had put build artefacts into fix commits. (7) CI (GitHub Actions) runs `make test` on Python 3.11, 3.12 and 3.13, plus a real-benchmark integrity job. `make setup && make test` passes in a clean `python:3.11-slim` container. (8) The README is half as long, with results and limits first. Not done, because they are outside this session's authority or means: a live-model score (no funded DeepSeek or Qwen key), a `main` branch (project rule: never modify main), a LICENSE (the owner's choice), and rotating the exposed keys (owner action).
- 2026-09-27: (1) Ablation switches: `[run] ablate` or `LCC_ABLATE=planner,reviewer,intake` skip those model calls, and `make ablation` runs the real benchmark for each variant, so that each call must earn its tokens with measured results. Offline, all three switched off leaves only coder calls, and tasks still resolve. (2) `sandbox = "auto"` is the new default: auto mode on a repository runs in Docker whenever Docker is running, and otherwise warns that the code runs on the host. `make run` keeps the host venv. (3) The process variables set by `setup_env` (`LCC_SANDBOX`, `LCC_SANDBOX_VOLUME`, `LCC_TEST_PYTHON`) are restored after each `solve()` or `auto_fix()`. The auto-mode Docker choice had leaked into later runs. (4) A contract test drives the whole orchestrator through `OpenAICompatibleProvider` against a strict fake server that rejects unanswered tool calls, null content, unknown roles, malformed schemas and JSON mode without "json". It passes. Still open, and outside this session: a live score (no key), `main` branch, LICENSE, key rotation.
- 2026-09-27: Three proof features (no model calls: test runs only). (1) Proof-carrying fixes: each verified commit writes `proof.json` (base, head, kind, targets, mutation), copied to `outputs/<task>.proof.json`. `lcc verify` / `make verify` replays it in a throwaway worktree (base sources plus the fix's tests must fail; the head must pass). PRs end with "Verify it yourself": plain git and pytest steps, no harness needed, checked by a test that executes them. (2) Test strength: after fail-to-pass succeeds, `proof.mutation_check` breaks up to 6 of the lines the fix added, one mutation each (comparisons, and/or, not, True/False, ±1, number+1, return→None, raise→pass), and never inside string literals or comments, because those mutants are invisible to any test. The score is recorded and shown in reports and PRs. `LCC_MUTATION=gate` sends a fix back once when its test catches none of 3 or more breaks. On the 20 real tasks the maintainers' own tests catch 24 of 29 breaks. (3) AI honesty ledger: auto mode counts claimed, dropped (no trigger / low confidence / unread file), attempted, proven and unproven model findings, and prints and stores the proven rate.
- 2026-09-27: Auto mode does the whole job. (1) The model audit reads the whole repository (`[auto] audit_scope = "full"`), most central files first, up to `audit_budget_chars` (120k chars, about 30k tokens). Large files are split into numbered windows, and a coverage record (files and lines read, unread files) goes into the report. (2) Every finding, whether from failing tests, the defect checker or the model (including dropped ones and the reason), goes into a ledger. It is written to `outputs/ISSUES-<repo>.md` with its final status and PR link, and each PR lists the other issues found. (3) An optimization is accepted only with a measured speed-up. The coder writes `.lcc/bench.py: bench()`, the verifier times it on the base and the new sources (warm-up plus the median of 7 runs, same interpreter and sandbox as the tests), and requires every test to pass and a speed-up of at least `min_speedup` (1.1). `.lcc/` is excluded from diffs and commits. Tested: O(n^2) → set is more than 5× faster and accepted; an unchanged "optimization" is rejected.
- 2026-09-27: `make run` opens the pull request itself. After a proven fix, `session.fix_and_pr` pushes `lcc/<task>` and opens a draft PR on the user's GitHub repository (or from their fork, after confirmation, when they cannot push). The PR targets the branch the fix was built on and includes `Fixes #N` when the fix came from a GitHub issue of that repository. `PR=0` keeps the fix local. Requests to optimize or speed code up are detected (`detect_kind`) and verified with the measured speed proof instead of a failing test. The push-permission check reads only the first field of the answer.
