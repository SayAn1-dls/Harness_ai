# Decisions

Append-only product decisions. Prefer `DECISION` events in `events.jsonl` for task-local choices.

- 2026-09-26: Python 3.11+ harness; pydantic schemas; filesystem event sourcing.  
- 2026-09-26: Model adapter protocol; mock default; OpenAI-compatible optional.  
- 2026-09-26: tree-sitter not required for v1; Python `ast` + regex. Embeddings secondary.  
- 2026-09-26: unittest for target repos so verification does not depend on pytest being installed in the target.  
- 2026-09-26: Human approval required before `gh pr create`.
- 2026-09-26: LCC is its own git repo (the enclosing `~/.git` is the user's home dir and must not be touched). Work on `agent/core-loop`.
- 2026-09-26: Real backends are DeepSeek and Gemini via their OpenAI-compatible chat-completions + function-calling endpoints (one adapter, presets in `lcc.model.PRESETS`). A missing API key is an error; there is no silent fallback to mock.
- 2026-09-26: The coder is a tool-using loop (`lcc.agent_loop`), not single-shot JSON. Observations are bounded (6k chars); identical calls are warned then stopped; tokens and runtime are metered per model call (`MODEL_CALL` events).
- 2026-09-26: Scope policy: forbidden paths (`harness/**`, `.git/**`, plan.forbidden_files) are hard-blocked; writes outside plan.allowed_files are allowed but recorded as `scope_expansions` and shown to the reviewer (`scope_mode="strict"` refuses them instead).
- 2026-09-26: Verification needs proof, not just a green suite: a baseline run is recorded before the first attempt; a pass requires either previously failing tests now passing, or changed/new tests that fail on the base code (sources temporarily reverted) and pass with the change. No changes means not verified. Zero collected tests is not a pass.
- 2026-09-26: Intake escalates on `blocking_ambiguities` (a question only the requester can answer) instead of guessing.
- 2026-09-26: Context gate is enforced for repos with more than 8 files: below 75 after expansion and a read-only context-agent pass means ESCALATED/missing_context. The snapshot score was recalibrated to measure relevance (the old score rewarded file count). Known weakness: `relevant_files` is self-referential (top-ranked vs selected).
- 2026-09-26: Compaction is deterministic: once an agent's working context exceeds 24k tokens, old tool observations become one-line stubs (the 6 most recent are kept). No summarization model call.
- 2026-09-26: Routing is opt-in: `LCC_MODEL_FAST` serves intake/recovery/review/context; `LCC_MODEL_STRONG` serves planner/coder on Lane C or after 2+ failed attempts.
- 2026-09-26: Hackathon evaluation interface. The root `Makefile` exposes `setup`, `run`, `test` and `clean` (plus `eval`, `doctor` and `distclean`). `make run` launches `lcc start`, an evaluation-mode session that accepts an issue as a GitHub URL, a file, pasted text, or stdin. Harness code runs from source (`PYTHONPATH=src python -m lcc`), so it never depends on editable-install `.pth` files.
- 2026-09-26: The only credential is `AI_API_KEY`, read from the environment at runtime and never written to files. Per-provider variables remain only as a local-dev fallback. The model is defined in `lcc.config.toml`: temperature 0.0, and `seed` is sent only to providers that accept it. `provider="auto"` maps the key format to an OpenAI-compatible preset and probes `/models` only for an ambiguous `sk-` key. The environment variables `LCC_PROVIDER`, `LCC_MODEL` and `LCC_BASE_URL` override the config without code edits.
- 2026-09-26: Target repositories are cloned into `workspaces/` (URLs) or used in place (local paths). Each gets an isolated venv (`workspaces/.venv-<name>`) with its dependencies, and `LCC_TEST_PYTHON` points the test tools at it. After each issue, unverified work is parked as a commit on the task branch and the repo returns to its original branch. `/harness/` is added to the target's `.git/info/exclude`.
- 2026-09-26: QA hardening of `make run`. Before a run, the user's uncommitted changes in the target are stashed and restored afterwards. They are never committed into the fix and cannot be destroyed by a rollback. A re-run of an issue whose `agent/<id>` branch exists gets `<id>-2`, `<id>-3` and so on, so it starts clean and does not overwrite the earlier patch. A repo with no commits gets a snapshot commit. Empty piped input, and setup errors, exit with code 2 instead of 0 or a traceback.
- 2026-09-27: The organisers announced that the final evaluation uses DeepSeek and Qwen models. The `qwen` (DashScope international) and `qwen-cn` presets were added beside `deepseek`. With `provider="auto"`, an ambiguous `sk-` key is checked with `GET /models` (no tokens spent) against DeepSeek, then DashScope international, then DashScope China, and never against any other vendor. The answer is cached for the process.
- 2026-09-27: `AI_API_KEY` is the only credential variable; the per-provider fallbacks were removed. A placeholder key (for example `your-key`) is rejected before any request is made.
- 2026-09-27: Before any work, a preflight sends one tiny completion from `make run`, `make doctor` and `make eval`. Account errors are `fatal`: 401 key rejected, 402 balance, 403 not allowed, 404 or model-not-found, and the quota or arrearage texts. They stop the session or benchmark at once instead of being retried per task. An unpinned default model that the account does not serve falls back through the preset's list (deepseek-chat → deepseek-reasoner; qwen3-coder-plus → qwen-plus → qwen-max → qwen-turbo). A pinned model (`[model].model` / `LCC_MODEL`) never falls back.
- 2026-09-27: The provider adapts to the server. A rejected parameter (`enable_thinking` for Qwen3, `response_format`, `parallel_tool_calls`, `seed`, a large `max_tokens`) is fixed or dropped, retried once, and remembered. A server without function calling gets the tools described in the system prompt, and `<tool_call>{...}</tool_call>` blocks (Qwen/Hermes style) or fenced JSON calls are parsed from the reply. `<think>` reasoning is stripped. Assistant tool-call messages send `content: ""`, never null.
- 2026-09-27: Verification compares test sets with the baseline instead of requiring a fully green suite. Failing test IDs are parsed for pytest, unittest, go, cargo, jest/vitest and node tap. A change passes when no test that passed at baseline now fails (pass-to-pass), and a baseline failure now passes or a new or changed test fails on the base sources (fail-to-pass). A full suite that exceeds `run.test_timeout` (900 s) falls back to the targeted tests: changed tests, plus tests named after the changed modules.
- 2026-09-27: Token efficiency: a later read of the same lines replaces the earlier read with a stub; passing test runs render as one line and failing runs as failures only (pytest `-rfE --tb=short`); observations are capped at 5k chars; compaction starts at 16k tokens. The coder gets a warning 3 steps before `max_steps`. Tool schemas were shortened by about 40%. The coder prompt asks for independent lookups to be batched in one turn (Qwen presets send `parallel_tool_calls`). JSON agents use `response_format=json_object` where supported, to avoid repair calls. Issue text is cut to 8k chars. Lane A skips the planner model call. Measured with a scripted 16-step session and identical steps, prompt tokens fell from 120,783 to 97,424 (−19%).
- 2026-09-27: The coder tools now include `shell` (git-state and destructive commands blocked, including `git -C . reset`; timeout clamped to 1–600 s; `python` resolves to the target's venv) and `git_history` (log/blame). Search respects `.gitignore` and takes a regex and a path glob. `edit_file` tolerates trailing whitespace, CRLF and pasted `N| ` line prefixes, never guesses indentation, points at the closest lines on a miss, and supports `replace_all`.
- 2026-09-27: Repository handling. A local path that is not a git repository root is copied into `workspaces/`, so the harness never runs `git init` inside another repository. `BASE=<sha>`, `REPO=<url>@<ref>` or a `Base commit: <sha>` line pins the base commit (detached checkout, and the original branch is restored). JavaScript targets get `npm ci` / `npm install`. Go (`go test ./...`), Cargo and npm test commands are used for non-Python projects.
- 2026-09-27: `make test` runs the unit tests and the offline scripted benchmark on all 7 tasks, each graded by its hidden check (`--min-resolved 7`).
